# 证据核查与自适应检索：科研软件开源任务理解方法

## 研究目标

科研软件开源仓库中的 Issue 往往需要结合源码、测试和项目文档才能理解。仅看 Issue 容易误判修改目标；只做一次静态检索可能引入无关材料；过严的证据过滤又可能删掉有用的合理推断。

本研究比较四种分析方式，观察源码证据、逐条核查和缺口补检与模型辅助评分之间的关系。研究针对固定仓库快照上的任务理解，不判断历史修复预测能力，也不判断任务当前是否可以认领。

## 方法流程

当前工程实现已迁移为LangGraph＋LangChain：LangGraph管理状态、节点和补检条件边，ChatDeepSeek负责模型调用。已报告的156份答案由迁移前的Python编排版本生成；方法规则复用，但不可把历史评分标注为LangGraph运行效果。实现细节见 [LangGraph工作流](LANGGRAPH_WORKFLOW.md)。

1. 读取 Issue 标题和正文；不向模型提供评论。
2. 在固定 commit 的源码快照中检索源码、测试或文档片段，为证据记录路径、行号和快照身份。
3. 模型按统一结构解释任务目标、知识要求、新手入门门槛、入手步骤、验收要求和未知项。
4. 对目标、技术要求、阶段判断和验收条件逐条核查，区分直接支持、合理推断、部分支持和依据不足。
5. D 组对缺少证据的结论生成具体检索词，补入新证据后重新分析；最多补检两轮。Issue 明确要求与模型提出的建议验证项分开标记。

能力阶段表示完成任务所需的最低能力，不代表某个具体用户的能力。材料不足时可以暂缓；有证据链支持的合理推断可以保留并明确标注。

## A/B/C/D 消融条件

| 条件 | 输入和处理 |
| --- | --- |
| A | 只使用 Issue 正文 |
| B | Issue 加首次固定检索到的源码、测试或文档 |
| C | 在 B 基础上逐条核查证据并筛选输出 |
| D | 在 C 基础上针对证据缺口补检，之后重新分析和核查，最多两轮 |

四组采用同一 DeepSeek Flash 分析模型和分析结构。C/D 的核查及 D 的补检增加额外调用，实验记录调用数、Token、耗时和停止原因；四组总成本并不相等。

补检在以下情况停止：结论均获支持、没有明确检索词、未找到新证据、达到两轮上限，或发生模型、检索及预算错误。输出保留每轮材料及最后一轮完整分析。

## 样本与数据隔离

初始冻结协议含45个任务：Manim、SymPy、Dask、Ray各10个，napari 5个。用于方法调试的六个任务被排除：首轮试点 Manim #2379，以及五项目各一个调试样例。正式留出集为39个任务：Manim 8、SymPy 9、Dask 9、Ray 9、napari 4；每项任务运行 A/B/C/D，共156份答案。

协议固定 Issue 文件、源码 commit 与 ZIP 哈希、规则及开发样本排除清单。验证入口：

```powershell
.\.venv\Scripts\python.exe research.py verify
```

正式实验入口：

```powershell
.\.venv\Scripts\python.exe run_final_experiment.py
```

在 PyCharm 中也可直接运行 `run_final_experiment.py`。当前默认生成LangGraph版本的新结果，目录为 `experiments/frozen_20261017/langgraph_heldout_v1/`；运行被打断后重跑会复用该版本已经完成的条件。

历史156份答案及评分在 `experiments/frozen_20261017/final_heldout_v3/`。仅继续历史评审时使用 `run_final_experiment.py --phase review --output experiments/frozen_20261017/final_heldout_v3`。

## 模型辅助评审和当前结果

所有156份答案由 DeepSeek Pro 按匿名条件进行模型辅助评审，输出0至4的等级分，评价正确性、完整性、主答案可操作性和原始入手指导性。模型参考点由评审模型从共同证据中生成；**没有人工 Gold 或人工复核**，因此这些分数不是准确率，也不是人工标准答案。

| 条件 | 正确性 | 完整性 | 主答案可操作性 | 原始入手指导性 |
| --- | ---: | ---: | ---: | ---: |
| A | 3.41 | 2.54 | 2.23 | 3.05 |
| B | 3.46 | 3.03 | 2.62 | 3.69 |
| C | 3.18 | 2.62 | 2.44 | 3.62 |
| D | **3.56** | **3.13** | **2.92** | **3.85** |

这组自动评审结果中，D 的四项均分最高；C 低于 B，提示逐条过滤可能过于保守，而补检可能补回部分有用信息。该发现仅描述本数据集和本模型裁判给出的等级分，不能据此声称统计显著或真实准确率提高。

能力门槛另有一致性复核，结果未覆盖全部39个任务；该指标不计入上表，也不作为全样本结论。逐任务模型理由见 `experiments/frozen_20261017/final_heldout_v3/model_judge/` 中的 `model_evaluation.md` 和 `stage_review.md`（专项复核文件生成后）。

## 主要限制

- 评审由单一模型系列自动完成，生成模型与评审模型虽不同，但仍可能有共同偏差。
- 0至4级分数是主观模型评价；五个项目的39个留出任务不足以代表全部科研软件仓库。
- 当前没有人工 Gold，不能报告人类准确率、召回率、评审一致性或统计显著性。
- 采集的是固定版本仓库快照；演示统一将任务按待解决情境解释，不代表实时开放状态。
- 原型演示和 A/B/C/D 实验是两项相互关联但不同的产物；门户本身没有实验条件切换面板。

因此，当前结论是模型辅助的探索性对照观察，用于呈现方法设计、流程可运行性和待改进点。
